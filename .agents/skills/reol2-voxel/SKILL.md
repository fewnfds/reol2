# Reol 2 体素开发

先阅读 `docs/prototype.md` 的玩家流程与验收条件。定位这次修改影响的规则、存档数据和 Unity 入口，选一个最小场景复现。

## 方块和派生数据

- 方块 ID 和逻辑坐标记录世界状态。Chunk 的 Mesh、碰撞和可通行位置从方块派生。放置、挖掘与读取存档走明确的数据写入入口。
- 检查坐标到 Chunk 的转换、负坐标和 Chunk 边界。编辑边缘方块时，邻块可见面会受影响。异步结果采用前检查输入版本仍然有效。
- 验证待更新的碰撞、渲染与通行之间的时序。放置请求检查占用，路线搜索检查体型所需空间和脚下支撑。

## 观察结果

- Edit Mode 适合验证方块索引、边界失效、路径和存档往返等规则。Play Mode 检查玩家控制、物理、角色工作与场景重开。
- 走一遍正常通行、改道、完全受阻和修路恢复。保存时选一个正在搬运或受阻的时点，重新加载后检查世界和工序是否接续。
- 性能对比使用相同种子、摄像机范围、活跃角色与编辑序列。记录有效完成量、帧时和待处理队列，再决定局部更新、合批与并行的范围。
