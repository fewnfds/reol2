# 大陆体素存储与流送选型

2026 年 11 月 21 日。Reol 2 的主方案采用**可复现生成器、固定 8 米三轴页、按页稀疏保存改动、近处构网和沿移动方向预取**。沿用 1 米编辑格与 0.5 米浮点密度采样。这个规格用于和现有大陆做可重复对照。后续由容量测试决定页宽、压缩精度和视距。[世界引擎主线](world-engine.md) · [现有大陆基准](../continent-demo.md)

下文的密集容量按现有两公里大陆计算。完整坐标域的随机总图和容量对照见[随机大世界方案](large-world.md#世界尺寸要和运行负载分开)。

## 34 GiB 是怎样算的

| 假设把整个范围都填满数组 | 数据项 | 理论容量 |
| --- | --- | ---: |
| 2,048 × 2,048 米平面，`Y=-96…176`，共 272 米高 | `4,097² × 545` 个 0.5 米网格采样点，每点 4 字节密度 | 34.08 GiB（36.59 GB） |
| 同样平面，只算 `Y=-256…0` 的 256 米 | `4,097² × 513` 个密度采样点 | 32.08 GiB |
| 同样平面，底部从 `-96` 扩到 `-256`，保留顶部 `176` | `4,097² × 865` 个密度采样点 | 54.09 GiB |
| 同样平面，只算 `Y=-256…0`，用 1 米格 | 每个 1 米逻辑格存 1 字节材质编号 | 1.00 GiB |

密度的正负决定内外，数值参与坡面位置与法线插值。前三行把空气、海水和岩石占据的空间都算进了密集数组，开销只包括密度。当前大陆常驻的是粗高度图、有限的附近页、网格与碰撞。`257²` 个粗高度浮点值约 258 KiB，构网复用一个 `19³` 浮点样本缓冲约 26.8 KiB。其他开销来自网格、碰撞烘焙和本次运行的编辑记录。[底场源码](../../Assets/Reol2/World/ContinentField.cs) · [构网源码](../../Assets/Reol2/Voxels/MarchingCubes.cs)

## 1. 按需生成和预取

**原始地貌由世界坐标决定。** 输入世界种子、生成规则版本和坐标，可重复算出同处的原始密度、地层与默认材料。地表轮廓和洞穴的空间包络先低成本生成。玩家挖填只覆盖改变的样本。读取时，先取这个坐标可靠的编辑值，否则从已确认的底场查询。保存版本与种子时锁定实际生成器配方，包括噪声实现。旧存档调用旧配方，升级配方需要明确迁移。[Voxel Tools Generators](https://voxel-tools.readthedocs.io/en/latest/generators/) · [Voxel Tools Streams](https://voxel-tools.readthedocs.io/en/latest/streams/)

| 情况 | 地形系统怎么处理 |
| --- | --- |
| 远处暂时没有取样，也没有查它的编辑页 | 可以画程序生成的粗轮廓。等请求到来，再查该处及其边界依赖的存档状态。默认无需为每个坐标建表。 |
| 成功确认没有编辑覆盖，或相关覆盖已取到 | 真实数据可求值，再判断是否需要构网与碰撞。优先使用本次游戏中尚未刷盘的改动。 |
| 有改动待加载，或读取失败 | 相关区域保持待确认。移动只在已就绪范围内，落点和支撑判断等待可靠状态。磁盘查错保留最后有效状态并报告。 |
| 当前样本范围可证明全实或全空 | 只在活动范围登记分类，跳过逐点取样、网格与碰撞对象。传送等需要新落点的操作单独检查空间是否为空。 |
| 有表面且实际碰撞已准备好 | 让局部真实地形接管，逐步替换远景代理。编辑生效时，近处画面和碰撞跟同一修订。 |

这里分别判断存档是否齐全、几何是否有表面，以及控制器能否进入下一段。原型的 `ready[chunk] == null` 只表示已处理的页没有三角形。引入磁盘后要能表示可证实的全实、全空和待读状态。Luanti 的接口也把未加载节点与空气区分，并把已有内存、磁盘载入和新生成分开报告。[Luanti 地图读取与 emerge 接口](https://api.luanti.org/core-namespace-reference/)

**用范围证明跳过全实与全空区。** 现有底场是 `密度 = 标高 − 地表高度`，并叠一处解析洞室。针对整个页和法线边界取高度的保守上下界。包络内没有洞穴或改动，且最高的样本仍在最低的地表下方，就能跳过全实页。复杂洞网用洞室或隧道的空间包络缩小求值区域。未来换成可能过冲的样条高度、3D 噪声或新增地质操作时，范围也需要覆盖这些变化。角点碰巧都在岩里时，区块内部仍可能有洞。范围算不清时，走完整取样与抽壳。参照 Voxel Plugin 的调试选项，加入可关闭早退的对照模式。[Voxel Tools 范围分析](https://voxel-tools.readthedocs.io/en/latest/performance/#sdf-clipping-cpu) · [VoxelGeneratorGraph 源码](https://github.com/Zylann/godot_voxel/blob/4b29b07817230bfc28a542b17e7d39a7ef5fcb91/generators/graph/voxel_generator_graph.cpp#L770-L833) · [Voxel Plugin 生成性能](https://docs.voxelplugin.com/1.2/technical-notes/performance-and-profiling)

**把玩家即将踩到的地方放队首。** 保留角色四周的基本安全圈和刚经过区域的短期缓存。用意向速度预测一条带体型余量的走廊，给脚下、飞行前方、潜水预计遇到的海床和洞口优先准备数据与碰撞。视野外的预取可以被急转向取消，加载的年龄从首次请求算起。距离取 `速度 × 走廊就绪时间 P99 + 制动距离 + 一段页边界余量`。就绪时间包含排队、磁盘读、生成、构网、烘焙和挂载。负载超过吞吐时先削减非关键细节，粗远景仍可看见，移动按剩余安全距离减速，扫掠检查在末端保底。传送前显式准备落点周围。[World Partition 的速度排序参数](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Engine/FWorldPartitionStreamingSource) · [Voxel Tools 流送与生成块缓存](https://voxel-tools.readthedocs.io/en/latest/api/VoxelLodTerrain/)

## 2. 同值合并和挖开再拆分

Voxel Tools 的 `VoxelBuffer` 将整个通道的同值存成一个默认值。第一次写入不同的值才分配该通道数组，再写相同值没有分配。OpenVDB 的 tile 覆盖更大范围，修改一个不同值时只沿这条分支建子节点，可把相同值和活动状态的子树折回 tile。Reol 2 用规则页承接同一做法，天然岩层可以由配方直接表达，少量变化先建例外记录。全世界无需预分配一层页节点。[VoxelBuffer 首写源码](https://github.com/Zylann/godot_voxel/blob/4b29b07817230bfc28a542b17e7d39a7ef5fcb91/storage/voxel_buffer.cpp#L302-L327) · [OpenVDB 的 tile 与 prune](https://www.openvdb.org/documentation/doxygen/overview.html) · [OpenVDB 首写源码](https://github.com/AcademySoftwareFoundation/openvdb/blob/f28614d90ce02736865e5db1da10b931f78e67a3/openvdb/openvdb/tree/InternalNode.h#L1972-L1987) · [Museth 2013 论文](https://ken.museth.org/OpenVDB_files/Museth_TOG13.pdf)

| 合并的对象 | Reol 2 的选择 |
| --- | --- |
| 同一种材质、未单独受损的岩层 | 默认材料读地层规则，真正同值的页可以共用一个材质编号。只有异材格需要覆盖，另存实际受伤格的耐久。几何仍读自己的密度。 |
| 未改、远离表面的整片深岩 | 可以用全实分类跳过构网。第一版保留底场原值，挖到时或相邻页抽壳需要时才取样。 |
| 材质相同、形状不同的坡和洞 | 保留近处实际密度，继续用 Marching Cubes 提取平滑表面。如果绘制提交成为瓶颈，可像 Voxel Plugin 一样合并同材质同 LOD 的渲染网格，碰撞仍分小块。方块项目 Sector's Edge 合并可见平面来省三角形，可作为将来规则建材的对照。 |
| 岩石是否会整团坠落 | 由空间连接与地基支撑决定。材料压缩之后照样能计算局部连通。同材质的两团石头可以一团落下、一团留在原地。 |

举例，跨页一条 0.5 米边两端是 `-0.25` 与 `0.25`，零面在边的中点。若把负侧的样本替换成统一的 `-1`，零面会从距起点 0.25 米移到 0.40 米。法线也使用邻居的实际差分。首轮把**整页同号的证据用于跳过工作**。有表面的地方照旧使用浮点样本。定点化、窄带截断或粗分辨率采样，先做局部测量再选。[Marching Cubes 取样与插值](../../Assets/Reol2/Voxels/MarchingCubes.cs) · [Voxel Tools 截断边界的说明](https://voxel-tools.readthedocs.io/en/latest/performance/#sdf-clipping-cpu) · [Voxel Plugin 渲染块合并](https://docs.voxelplugin.com/1.2/technical-notes/performance-and-profiling) · [Sector's Edge 开发记录](https://vercidium.com/blog/voxel-world-optimisations/) · [NVIDIA Blast 支撑图](https://docs.omniverse.nvidia.com/kit/docs/blast-sdk/latest/docs/api/introduction.html)

### 具体怎么存一页

1. **唯一所属页。** 8 米对应 16 个 0.5 米步长。整数样本索引用向下取整除以 16 得到页坐标，用非负余数得到页内 `0…15`。每页最多管理 `16³` 个独占采样位置。构网需要的 `19³` 包含相邻页数据，用同一底场和编辑快照临时拼装。在完整坐标域，正边界面使用同样的归属公式，落到几何范围外的键仅承载闭合端点的样本和编辑。外侧 halo 读取对应的闭合端点。边界只写一份真实值，编辑后标记到所有读取该范围的视图。[世界坐标与生成契约](large-world.md#世界坐标与生成契约)
2. **页内只记录不同的值。** 保留现有挖填的 `min/max` 和放置来源。将全局样本字典换成按页索引，其下用页内编号定位绝对密度和来源。首次写只为发生变化的页和样本建记录。构网时先顺序采样底场，然后叠加工作区需要的改动，避免循环里对每个样本查全局表。保留批量改动前后对应的页修订。
3. **同值折叠比较语义。** 土填回来肉眼相同，仍可能改变样本值、放置来源或材质。只有与同版本底场逐值等价且覆盖语义也恢复时，才可以撤掉对应覆盖。整页被挖空时，存档必须保留明确的挖空结果。已落盘页恢复到底场后保留一条待删除记录，成功提交删除前优先按底场读取。运行时回收了覆盖记录也要让在途任务看到新修订。
4. **密集页再换表示。** 首版保存排序后的 `ushort` 页内编号和 `float` 密度，来源单独编码。若很多页高频改写或接近填满，对照 `4096 bit` 的存在位图加按位次存值的格式。字节和反序列化耗时共同决定切换。高密度是否适合在内存拆成连续数组，单独测，不和落盘格式绑死。

下表是密度载荷的算术核验，不含来源、记录头、托管容器、数据库或压缩成本。一个 1 米刷子最多触及 27 个半米采样点，在页角可分属 8 页。密集改动可从位图格式获益。

| 8 米页中改了多少样本 | 稀疏编号和值 | 位图与连续值 |
| --- | ---: | ---: |
| 27，单格刷最密时的上限 | 162 字节 | 620 字节 |
| 560，2 × 3 米隧道贯穿一页的覆盖示例 | 3,360 字节 | 2,752 字节 |
| 全部 4,096 | 24,576 字节 | 16,896 字节 |

## 3. 落盘与内存预算

选用**单存档 SQLite、以三轴页坐标为键、改动页保存有版本的二进制记录**作为 E2 的第一验证路径。Voxel Tools 有长期使用的 `VoxelStreamSQLite` 实现，也区分成功查无该块和查询出错。在 Reol 2 先用当前 Unity Windows Player 验证 SQLite 绑定和事务，再接游戏场景。页数据编码独立于存储接口，Windows 绑定可用性是这项计划尚需确认的前提。[VoxelStreamSQLite](https://voxel-tools.readthedocs.io/en/latest/api/VoxelStreamSQLite/) · [流送读块源码](https://github.com/Zylann/godot_voxel/blob/4b29b07817230bfc28a542b17e7d39a7ef5fcb91/streams/sqlite/voxel_stream_sqlite.cpp#L201-L237) · [SQLite 原子提交](https://www.sqlite.org/atomiccommit.html)

- **事务和版本。** 存档头记录世界 ID、种子、生成版本、页与样本尺度、编码版本及最近提交标记。页记录校验坐标、字段长度、数据范围和完整性。一次提交包含完整的跨页改动、删除及提交标记，使用一个后台写入者。回写成功后，只清除与已写快照修订一致的脏标记。E5 的岩体和源页扣减可以加入同一次事务，等出现该用例再增加实体表。
- **覆盖的读优先级。** 活世界从本次未保存的改动和待删除记录读取，然后取已提交的覆盖。背景读取绑定世界会话、请求代数和页修订。构网使用一致输入窗口，发布时核对 halo 涉及的各输入页修订。适逢编辑或卸载重载时丢弃过期结果。查错、待查和成功确认不存在分别返回。一次取近处范围的覆盖可合并相邻 halo 查找。若空区域查询妨碍飞行，比较按区域加载的存在性摘要和常驻编辑坐标集合的启动、冷查询和驻留字节。摘要只有覆盖范围完整且对应同一提交时才能证明某页不存在，内存中的更新优先。
- **按字节控制在途工作。** 分别跟踪脏覆盖和待删除、在途快照、已保存缓存、派生网格与碰撞字节，以及最老未写年龄。改同一页时合并较旧的待写状态，保留已经交给写入者的不可变快照。压力上来先收紧新的快照和远处预取。逼近内存上限而写入追不上时，接受下一笔改动前给出可观察的保存繁忙或失败状态。存储错误时保留上一份已提交存档与仍在内存的有效改动。成功写盘前，活动视图卸载不会释放权威覆盖。
- **读、写和恢复分开量。** Unity 主线程做已验证数据的发布，磁盘 I/O 在后台。分别记录读排队、校验解码、事务耗时、快照内存、碰撞就绪。SQLite WAL 是有读写并行需求时的对照选项。若启用，验证长期读取对检查点及 WAL 文件体积的影响，监控写尾时延和退出后的恢复。[SQLite WAL 与检查点](https://sqlite.org/wal.html)

### 存档验收

1. **先做顺序敏感的对照。** 在负坐标页角挑两格共享样本，找到两种执行顺序确实产生不同密度的挖填动作。对照未保存和重开后的实际样本、法线、碰撞、再次选中凸土的格和放置来源。拒绝保护区、身体占用和无变化的操作要保持修订不变。
2. **失败写入与拒载。** 跨缝修改后保存 A，改变同一处并开始保存 B，在提交前中断进程后重开验证能完整读 A。改坏页载荷或用未知生成版本时先拒绝候选。另模拟第二个相邻页或碰撞准备失败，保持原会话可移动、可编辑，完整候选准备好才接回输入。
3. **重入与旧结果。** 改完飞离再回来，分别让旧读取在新编辑、当前卸载重进、已落盘页覆盖撤回之后才返回。核对仍用最新的样本和来源。对同页在写入中再编辑一次，先完成的旧写回不得清掉新改动。完全挖空的页仍能重启后读到挖空。
4. **慢盘、写失败和回落。** 固定路径逐步加快编辑频率，限制写速或令事务失败，再恢复写入。量脏页、快照字节、最老未写时间与重试后的回落。用 Windows 开发包从玩家入口保存并真正退出，再重开走进同一个洞、重新选格与填土。

## 4. 实施顺序与通过条件

| 次序 | 工作入口与明确结果 | 验收场景 |
| --- | --- | --- |

## 5. 评审结论与验证范围

首轮 Gemini Web 触发上游限额，启用了 AI Studio 双路。代码和数值复审用恢复后的 Gemini Web，Neon High 和 Neon Task 都给出结果。采纳的改动包括明确区分未查存档和纯实纯空、写入须保留共享样本来源、已落盘页恢复时延迟删除、用新路线验证预取。首轮提出直接物化为 16 位定点整页的做法会让一个角落的少量样本改动展开多页，且需重新验证光照、挖填和边界。优先采用精确的稀疏覆盖。

独立试算核验了 34.08 GiB 的数学口径，跨页角分配、密度示例的字节数与 0.15 米插值偏移。用 Python 自带 SQLite 确认了八个页键在同一事务提交、回滚后重开还能读取。E1 的走廊和取样数据见[大陆基准](../continent-demo.md#本机验证)。SQLite 的 Unity Windows 绑定、进程中断恢复和冷区读盘成本留给 E2。早期查阅和顾问记录存放在本机 `.local/research/sparse-world-2026-11-21/`。
