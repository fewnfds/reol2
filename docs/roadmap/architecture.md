地形 M1 对应大陆 E2。挖填的顺序会影响共享密度，存档保留生效后的精确样本和放置来源。流送与碰撞先按大陆 E1 验证。通行只重算与新发布几何修订相交的区段。矿工存档接入时验证货物交接与地形在同一边界提交。[存储与恢复](voxel-storage.md) · [流送、碰撞和近远交接](world-engine.md#3-连续流送与高速移动)

## 通行、决策与居民工作

- **近处支持面。** 第一名工人走在与玩家相同的已发布碰撞上。搜索候选点时看脚下表面、身体净空、坡度与步高，具名边用真实角色行走验证。初版可在两条设计好的走廊内取有限样本，以 A* 或很小的路径图找路。含上下叠层洞穴时每个平面坐标可有多个支撑高度，图边还要通过体型扫掠。只有实测表面方案撑不住才对比局部 Unity NavMesh 重建。
- **编辑影响范围。** 用本次已经发布的变化范围，再加角色半径、台阶和相邻边连接所需余量。测试同一改动影响当前路线和新开的路线。拒绝或没有效果的编辑保持原有通行状态。被挡的工人能停在最近的安全点，以对应的脏区版本或合理低频请求重新尝试。
- **工作动作。** 工人能到矿点领货、在途、等待、到站卸货。资源在矿点、携带者和工坊之间交接，每次登记明确数量。工作记录从领货到交付保持同一 ID。设施现在缺货、工人路被堵、目标仓已满有不同反馈。真实发生过两种以上用法后，再考虑将动作结构推广到做饭、种田或管理。
- **决策时间。** 当前需要与已有的任务决定下一步，世界时钟提供小步推进。需求变化、目的地被占或路径失效时才重新计划，限制重复请求。完成工作与刷新计划分别计时，积压时优先地下脚或近处正在执行的动作。远方采用能独立推进的粗规则，角色恢复接入时继续相同的工作。

Factorio 的开发记录提供一个成熟范式，先找适合长途的粗路径，再在需要的位置做精细搜索。动态变化时更新受影响的局部连通信息。Reol 2 最先用有限走廊和手工路段校验这条思路，扩张到存活聚落和大地图时才比较通用分层寻路。[Factorio 开发日志 #317](https://factorio.com/blog/post/fff-317)

## 从近处一趟货到远处一段历史

### 物资交接与存档一致性

- **一趟货例。** 起始为矿点 3、工人 0、工坊 0。取货后 0、3、0。受阻和离开时仍为 0、3、0。确认交付后 0、0、3。产出、损耗、掉落有明确原因。数量与阶段同一次推进更新。队列重复投递同一领货或交付意图时，依据工作 ID 与阶段拒绝重复结算。
- **存储切点。** 在已结算的处理边界捕获任务、库存、时间和必要的随机流，与本次地形改动一起提交。候选会话校验完数据并准备附近碰撞后再接回控制。[地形存档方案与异常验收](voxel-storage.md#存档验收)
- **支持范围。** 初期先做手动保存，退出重开从最后一次完整提交恢复。M2 增加“已取货、受阻、刚交付”三个断点，验证两个库存、载荷、工作阶段和角色已知信息彼此一致。

### 近远切换要处理的反例

玩家看见工人背 3 份矿刚过甲地起点，挖坏他前方的必经坡，再走开、读档或远距传送。正确结果是该人和货在同一合法侧继续等待，或沿已确认的绕路花费额外时间。工坊库存到实际到货才加 3。

1. 世界处理中先确认本次有效编辑与路段状态，再处理同一逻辑时刻的行程到站。给这种相遇写明确规则。对于已经出发的在途任务，保存进度、所在边、最后活动点和下一次检查时刻。道路变为待查或中断时保持待机，参考真实通行结果重新给 ETA。
2. 近处驱动者在安全点确认当前位置与阶段；释放它的推进权后，再把同一行程交给远区事件推进。回到附近时，由逻辑记录重建表现，在实际可以站立的入口锚点或路段恢复。没有安全落脚点就暂留在任务记录中的等待状态。角色、货物、结算仍沿用原 ID。
3. 标明本地区当前的路线版本。修改检测范围的数据先使相关边待复核。离屏时如果有满足前置条件的预置维修和已验证的通行结果，可在同一个模拟时刻提交编辑与通路结果，运输照常推进。其余路段以待查状态等待或使用已确认的替代路。逻辑地形修改已生效，区块生成时按对应版本再建碰撞，用已经记录的通路结论复核。玩家是否回场不应改变预置维修的完成时刻。
4. 小地图用两地、两条明确连得上的路线和一个商队。以后按需增加角色更新频率、群体密度和运输工作队列。近远参考半径分开设置，以观测到的切换频度和积压调整。远区每条路线共享路况和代价，日历上的事件推进替代高频 3D 搜索。

### 世界时间与随机性

- 世界规则使用整数逻辑时间，渲染帧给局部运动和表现。到期任务、到站、人员死亡及变更按明确的阶段优先级和持久序列执行，保存处理边界和必要的待办。对“同刻发生什么先算”的选择，优先用具体事件说明。比如到站提交前道路确认中断，运单保留。
- 固定种子复盘读同一初始档、同一外部请求和同一规则版本。在纯规则版记录输入与关键结算顺序。灾变、生产扰动和纯视觉随机各自使用隔离的流或派生种子。改镜头、增加动物表现或增加一个普通 NPC 不应影响不相干地区的灾变抽样。近处移动带来的真实输入由测试明确注入，核对关键结算与自然时间范围。
- 年代推进先重复可审核的小步或跳过确实无事件的空档。用几季小数据对照快进和逐日结果，核对人物生死、组织、路线、库存与关键事件。只有看到瓶颈才增加低分辨率的人口迁移和季节聚合。跨年推进可显示进度，到完整检查点才允许切回控制与保存。

## 测量矩阵

地形修改与流送已有各自的实测。表中其它场景是居民和地区模拟接入时的测量计划。[双块编辑基线](../prototype.md#性能测试) · [大陆流送基线](../continent-demo.md#本机验证)

| 试验 | 起始规模 | 至少记录 | 扩张判断 |
| --- | --- | --- | --- |
| 矿路工作循环 | 1 工人和 1 张单据，后来用 4、16 人做隔离压测，20 次堵路和修路。 | 当前工作阶段、改路后停住或换路的延迟、重算次数、待办排队年龄、资源守恒。 | 具名工人与两个库存一致，堵路和恢复可读。排队年龄走高时减少重复更新或活动路段。 |
| 行程与历史 | 2 地、1 商队开始。加至 8 地、20–50 条活动行程作为试验。 | 短途在途结算、旧路线停用、货物流量、事件延迟与真实世界回访。 | 地图载入顺序、反复生成场景人物和保存不改变该做的结算。出现规则推进变慢时先区分库存、路线或事件队列。 |
| 步行、编辑和近远交接叠加 | W7 的连续地图，一趟跨区运单、4 名近处居民与接缝编辑。随后试四块交角。 | 帧时、碰撞生效、路径失效与重算、卸载交接、队列高水位和等待年龄。 | 对比各子系统单独运行。只有可复现的叠加瓶颈值得调整加载、构网或路线预算。 |
| 年代推进 | 2 地、至少 3 个有名人物、两种外部扰动模式。先对照一季，再测 1 年和 20 年。 | 事件数与花费、耗时、可中断检查点、内存、档位体积、关键摘要和不变量。 | 若第一版 20 年试跑超几秒，保留短期推进并定位占用。准确性以同输入对照为准。 |
| 飞行加破坏 | 一条往返飞线、1 名玩家和定量的范围编辑。楼洞、斜坡与加载边界各一处。 | 速度、预取命中、碰撞提交延迟、P99、过期工作和内存。 | 预取距离至少覆盖速度 × 冷加载到碰撞就绪的尾延迟，再加制动余量。排队过长先限入场速度、半径或每次编辑体量。 |

一轮测量记 Unity 版本、构建类型、机器、分辨率、帧率限制、种子、镜头、加载/活动数量和编辑节奏。资源数量差、同一人物重复出现、悬空通行和迟到覆盖在复现用例里要求为零。帧时阈值先当实验条件。可用 CPU Timeline、Memory Profiler 或阶段计时代替猜测。构网、碰撞、可视对象或远区规则各自撞上预算后，才比较仿真频率、缓冲复用、Jobs/Burst、MeshData、分层寻路与 LOD。每次只换一个可归因变量。

## 短期工作可用的成熟范式

| 现在采用的做法 | 后续有证据才选择的扩展 |
| --- | --- |
| 独立的可试玩垂直切片，完成一个玩家行为与世界后果。 | 利用同一模式扩料理与农业，等出现具体重复后再做可复用的数据定义。 |
| C# 规则的单一状态写入、测试中可控时钟、可重复种子与回放用输入。 | 跨地区的事件调度与分析工具，规模需要时再评估数据布局、调度库或 ECS。 |
| 分两层寻路与视距/时间频率分离。 | 有实际城网和用户等待数据后决定自动门点、流场或 NavMesh 混用。 |
| 本机 Unity 场景验证、Windows 构建和基准，单 Linux 作业做仓库静态检查。 | 复用现有测试入口，是否增加自动 Unity CI 留给维护频度和额度证据决定。 |
