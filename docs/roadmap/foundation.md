# M1–M3 · 让地形、居民和小地图先连起来

现行技术主线是[大陆与体素世界引擎](world-engine.md)。本页保留第一次接入居民与地形的低成本对照，可在短路线和小据点完成。任务规格随证据调整。

## M1 · 挖过的地形可以重开

**玩家结果。** 修改坡面与跨区块洞口，选择保存。重开后能走过旧洞、瞄准刚填过的曲面并继续编辑。固定路头保持可站立。

M1 的地形交付随大陆 E2 实施。后续让矿工读同一份已发布碰撞和存档边界。[精确覆盖、故障和重开用例](voxel-storage.md#存档验收)

## M2 · 独立的矿工能继续工作

**玩家结果。** 在一个小据点看到外门弟子主动领矿。玩家挖断主路，工人走侧道；两条都断时停在安全侧并说明原因；修复新路线后交付手上原来的 3 份矿。保存点可能在领货后或受阻时。

| 小目标 | 前置及改动范围 | 可验收结果 |
| --- | --- | --- |
| **N1　摆出一趟货** | 用已可编辑的平滑地形做矿点与工坊，放一位角色、两处站点和一条能正常走通的短路线。标记主路和可开通的侧路。 | 玩家能在场景里从矿点步行到工坊，坡面可以正常走。控制台有具名站点与工人 ID。 |
| **N2　取货、携带、交付** | N1。用纯规则做一份运单的两次交接与工作阶段，交接有唯一工作 ID 和有效到达条件。 | 从 `3/0/0` 变到 `0/3/0` 再到 `0/0/3`。重复调用无新增，目的容器暂不能收货时留在携带者。 |
| **N3　角色实际走到站点** | N2。已有碰撞上用一个具体验证过的身体，高度、半径、坡度、步高和净空来自同一份设置。先完成独立的去矿点、领货、走到工坊。 | 工人可独立送货，经过坡面时不穿模，以到达条件结算。没有玩家在两站间触发动作。 |
| **N4　给短路段验证支持面** | N3。先做两条有限候选道路。用已发布碰撞取可站立表面，检查边的坡度、落差和障碍，记录有效修订。 | 主路、侧路各有一组可通过和不可通过的对照。隔着岩壁的两点不能因为平面相邻连边。 |
| **N5　挖断、绕行、等待、修复** | N4。把地形已发布的变化范围和修订通知通行检查。近处填土把工人的实际占用一起考虑。路线待复核时，工人使用当前可验证的一段或在安全点暂停。 | 开放走直路，主路断走侧路，双路断保留工作，修一条后接着送达。一次修改只影响相关路段。 |
| **N6　可读的居民反馈** | N2、N5。用携带动作或道具、站点库存提示和简短状态说明货在哪里、工人因何等待。 | 玩家不看调试面板也能区分“路断”“没货”“目标收不了”。到场看见实际更新过的库存。 |
| **N7　搬运中与受阻时保存** | E2、N5。把同一人物、工作、货与地形在同一个事务边界存入快照。读取后用新碰撞重新校验通路再推进。 | 堵路时工人手拿 3 份矿，退出重开再修路后交原货。已交付的工作再次读取不会重复发货。 |
| **N8　运行三至五分钟的小场景** | N6、N7。按“旁观一趟、阻断、修复、退进”做实机验收，再用同一地图做少量多人对照。 | 新局可直接找到工人和通路，四种路况均可复现。记录帧时、每次编辑影响的路线段数、寻路重算与待办年龄。 |

**扩张判断。** 若居民卡在平滑曲面，先定位采样、边的可走判断和身体参数。固定场能稳定后做 W0 的跨地区规则对照，记录物流及组织收支的差异。[W0 对照](world.md#w0--先验证两地因果)

## M3 · 小地图跨区走，并能卸载重进

**玩家结果。** 一次不读条的短程旅途中跨几个坡、山洞和区块。回来会看到同一条自己挖开的路，工人也不会因世界视图重新加载而忘了原工作。跨很远的旅行允许显式加载。

| 小目标 | 前置及改动范围 | 可验收结果 |
| --- | --- | --- |
| **T5　居民跨装卸的一致性** | E1、E2、N7。工人只保留一份主记录。视图返回时用当前地形、库存和工作状态恢复。 | 任意穿插改路、离场、返回和保存退出，回来只出现一个对应工人，原订单与货量一致。 |
| **T7　远程入口** | E1、E2。选择两个入口锚点，远距传送可有加载界面，落点附近的碰撞和会话数据准备后接回控制权。 | 连续近程可直接走，远传后能回原地。重复往返中角色始终保有安全着陆位置。 |

M3 先用唯一居民主记录。工人进入未模拟区域先保留携货与等待状态。近远两种模拟的推进权交接在 M4 验证。[流送与规模验收](world-engine.md#8-开发顺序与验收) · [自治地区](world.md)
