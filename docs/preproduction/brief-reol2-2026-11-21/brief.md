# Reol 2 游戏简报

本简报按 BMad Game Dev Studio 的 `gds-create-game-brief` 快速路径整理访谈。首个原型的优先级来自本轮回答，长期愿景和工程假设可随试玩与实测修订。

## 愿景与目标玩家

> 玩家作为任意有灵万物，在一个动态变化的沙盒仙侠世界中，通过探索与变强，获得角色扮演体验。

现阶段唯一的目标玩家是开发者本人。他喜欢以一个生命的视角游历宏观动态的大世界，围观并感受世界变迁，也希望有机会改变它。

## 核心玩法

一次游玩从扮演一个生命开始。玩家探索、成长，按身份做事，并在游历中遇见世界的变化。凡人经营、散修游历等可以有不同的日常行动，具体循环随身份逐步验证。

### 长期方向

- **世界自行演变。** 玩家离开后，NPC、组织和地区仍会发生变化，回到旧地时能感受到结果。
- **不同身份有不同活法。** 长期希望支持扮演有灵万物。死亡后可以在同一世界开启另一段人生。
- **玩家能亲手改变世界。** 可建造和破坏的地形是首轮要验证的交互，也是日后探索世界影响如何传递的起点。

## 参考作品

宏观参考《文明》《战锤》的势力与世界演变。微观参考《Kenshi》以个体身份在世界中生活、《Minecraft》的方块改造，以及第三人称动作游戏的操控。

## 制作条件与首个原型

Windows 单机，Unity 6.3 LTS、URP 和 C#。开发者负责玩法取舍和试玩，主要由 AI 实现和测试。先建立可走、可建造、可拆除的世界基础，剧情暂缓。

[ASSUMPTION] 首个验证场用一个角色和两个相邻区块，检验移动、放块、挖块是否能通过真实画面和碰撞形成闭环。区块数量只是试验规模。[首个原型与验收](../../prototype.md)

## 内容与美术

接受低精度、风格统一的低多边形人物与景观。自然地形希望能按格挖填，并有可以连续行走的缓坡。优先使用免费、CC0、开源或程序生成的素材。首个验证场用简单场景和占位角色起步，长期内容见[设计方向草案](../../design-direction.md)。

## 风险与未决项

开发者最在意的三类失败是世界看起来只是静态地图加脚本事件、身份很多但玩法一样，以及性能无法支撑超大世界演算。它们分别需要观察玩家离开后世界是否留下可见变化、比较不同身份实际能做的事，以及记录地形加载和世界演算各自的实测开销。

区块尺寸、活动范围、编辑吞吐量和帧时预算由试验确定。动态加载、存档恢复、远区演算和首批可玩身份的验证规模待定。
