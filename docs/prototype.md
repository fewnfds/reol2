# 首个玩法原型

## 三分钟的玩家体验

玩家从第三人称观察一名外门弟子在现成的小据点里采灵矿、运回工坊。玩家可以挖掉几块路面或在路上放方块。弟子发现当前路线受阻后改道，无路时保留工作并显示受阻。玩家在另一处铺回通路，弟子能继续送货。保存并重新进入场景后，方块改动、弟子位置、手上的货物和工序都能接续。

这个练习用于验证 Reol 的自主生活系统能否与可改地形产生玩家看得懂的后果。矿石和工坊是原型用例，数值、地图范围和居民规模都可以在测试后调整。

## 代码与验证顺序

1. **挖、放、行走。** 一个小地图跨越几个固定尺寸的 Chunk。每个 Chunk 保存方块 ID，派生合并后的可见面 Mesh 与近处碰撞。验证玩家能选中目标方块，边界编辑能正确更新相邻 Chunk 和碰撞。
2. **NPC 路线与工作。** 初版在体素网格上按可立足位置、身体净空与支持面寻路。受影响的方块改动使相关路线失效。验证开放、改道、完全封路和修复通道四种状态，并核对矿石从采出到交付的数量。
3. **保存和恢复。** 保存版本、地图标识、方块改动、角色与工作状态。验证在搬运中和受阻时退出重开，场景与库存可继续推进。
4. **性能基线。** 记录地图规模、活跃 Chunk 数、NPC 数、编辑速率以及 Mesh、碰撞、寻路更新的耗时。先在 Windows 开发构建上复测，再根据瓶颈使用 Jobs、Burst 或调整帧预算。远区模拟频率与 NPC 并发上限由实测决定。

本机顾问参与了原型构思。验收以实际的 Play Mode、测试结果和性能采样为准。
